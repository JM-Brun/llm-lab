# Embedding Atlas and Neuronpedia: focused pedagogical integration

**Review date:** 2026-11-17  
**Status:** documentation-level review plus bilingual activities integrated; research benchmarks and model-internals experiments were not reproduced.

## Executive synthesis

The two tools address different levels of representation analysis and should not be taught as interchangeable visualizers.

- **Embedding Atlas** explores vectors and associated records through projections, nearest neighbours, density-based clusters/labels, search, and metadata cross-filtering. Its pedagogical value is coordinated inspection: move from a visual pattern back to the original object and its metadata.
- **Neuronpedia** exposes evidence about model internals through SAE features, activations, logits, activation density, explanations, attention-head views, attribution graphs and (when supported) inference on custom text. It is not a turnkey explanation of model behaviour.

The integration reuses existing bilingual pages rather than creating new standalone chapters: Embedding Atlas is attached to the embedding-space deep dive and exercise hub; Neuronpedia is attached to the advanced contextualized-representations page and its exercise hub.

## 1. Embedding Atlas

### What the source supports

The official Apple research description identifies adoption friction (data preparation, loading, scale and workflow integration) and analysis friction (lack of coordinated views with metadata). The tool combines interactive embedding projections with density-based clustering, automatic labels, nearest-neighbour search, metadata cross-filtering, linked charts and multimodal/tabular fields. Its official CLI documentation exposes reproducibility-related controls such as UMAP parameters and a random seed, and options to provide precomputed coordinates and neighbours.

Sources:
- Project: https://apple.github.io/embedding-atlas/
- Overview: https://apple.github.io/embedding-atlas/overview.html
- CLI guide: https://apple.github.io/embedding-atlas/tool.html
- Apple research page: https://machinelearning.apple.com/research/embedding-atlas
- Paper: https://arxiv.org/abs/2505.06386
- Repository and software licence: https://github.com/apple/embedding-atlas

### Pedagogical integration

The bilingual activity asks learners to choose a documented dataset; record the embedding model/version, preprocessing, metric and provenance; predict a relationship between metadata and visible neighbourhoods before opening the map; filter metadata and inspect groups/outliers; inspect original records; and compare displayed neighbours with original-space neighbours where possible. Learners then vary projection/clustering settings and report sensitivity.

This is a question-driven investigation, not a product tour. It connects embedding geometry to distance metrics, nearest-neighbour search, clustering, and the difference between visual evidence and task evaluation.

### Critical boundaries

- Projected coordinates are not the original high-dimensional vectors. A 2D projection may distort distances, densities and shapes.
- A cluster depends on the representation, metric, algorithm and parameters. Automatic labels are descriptive hypotheses, not ground-truth semantic classes.
- Metadata cross-filtering can reveal confounders; it does not establish causality.
- Reproducibility requires recording dataset, model, preprocessing, metric, parameters and seed where available.
- The repository's MIT software licence does not automatically license paper figures or example datasets.

## 2. Neuronpedia

### What the source supports

Neuronpedia describes itself as an open platform for interpretability research, with datasets and tools for SAE features, MLP neurons, steering, circuit tracing/attribution graphs, attention heads and APIs. Its documentation distinguishes releases, sources/source sets, models and individual feature identifiers. Feature dashboards include activation examples, logits, density views, explanations and (for sources with inference enabled) custom-text activation tests. Auto-interpretability explanations are generated by AI models from selected activation evidence; methods and scoring procedures vary.

Sources:
- Platform: https://www.neuronpedia.org/
- Documentation: https://docs.neuronpedia.org/
- SAE overview: https://docs.neuronpedia.org/sparse-autoencoders/overview
- Feature dashboards: https://docs.neuronpedia.org/sparse-autoencoders/feature-dashboards
- Auto-Interp: https://docs.neuronpedia.org/sparse-autoencoders/auto-interp
- Key concepts: https://docs.neuronpedia.org/getting-started/key-concepts
- Search: https://docs.neuronpedia.org/sparse-autoencoders/search
- API: https://docs.neuronpedia.org/api/

The worksheet links the documented example gemma-2-2b/20-gemmascope-res-16k/10956. This is a concrete example, not a claim that the same feature index has the same meaning in other releases or models.

### Pedagogical integration

The bilingual investigation asks learners to record model, release/source, layer, hook and feature index; compare the text explanation with activation examples; search for counterexamples; inspect activation density and positive/negative logits without conflating their meanings; test custom text only if the source supports inference; and write a calibrated, falsifiable conclusion.

This teaches evidence inspection and hypothesis revision. It deliberately does not ask learners to memorize a feature label.

### Critical boundaries

- A feature is a learned direction/latent in a particular source; it is not automatically one unique human concept or a native neuron.
- Automatic explanations can be wrong, incomplete or overly broad. Scores are method-dependent and should be checked against actual examples.
- Activations indicate where a feature responds; logits indicate associations with output tokens. Neither alone establishes a full causal role.
- Attribution graphs depend on their methods and approximations. Steering is an intervention, but a changed output alone does not prove a complete mechanism; controls and counterfactual tests are needed.
- This review is documentation-level. No model weights were run, feature activations recomputed, or causal claims reproduced.
- No screenshots, figures or datasets were copied; no reuse permissions are inferred from public accessibility.

## 4. Synthesis and next research steps

The central distinction is between **exploring the geometry of a dataset** (Embedding Atlas) and **inspecting evidence about internal model features** (Neuronpedia). Both tools make complex objects visible, but neither visualization turns an interpretation into proof.

The activities follow the project's teaching pattern: learner question, prediction before interaction, controlled observation, explicit counterexamples, and a debrief connected to mathematical objects and evidential limits.

Remaining work for a deeper audit:
- reproduce one Embedding Atlas workflow with a pinned, redistributable dataset and documented embedding model;
- inspect the full paper's methods and benchmark protocol rather than relying on its abstract and official product documentation;
- select one Neuronpedia feature whose underlying release/paper can be read end-to-end, independently inspect its activation examples, and compare more than one explanation/scoring method;
- run controlled feature interventions/ablations only in a reproducible model environment, with baselines and counterfactual prompts.

Until then, both source records remain **partially-scanned** even though their bounded learning activities are integrated.
