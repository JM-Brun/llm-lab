# Learning-map page audit — 2026-11-06

**Repository:** JM-Brun/llm-lab
**Page audited:** `site/fr/learning-map.qmd` + `site/en/learning-map.qmd`, rendered at https://jm-brun.github.io/llm-lab/fr/learning-map.html
**Baseline:** main @ 8e57ba9 (the deployed Pages build predated it)
**Method:** source-level review of the page shells, the generator (`site/tools/build_learning_map.py`), the renderers (`site/tools/learning_map_renderers.py`), the route registry (`data/guided-route.yml`), the committed generated fragments, and the site tooling tests. No browser or screen-reader session was run.

## 1. Findings and dispositions

| ID | Priority | Finding | Disposition |
|---|---|---|---|
| LM-01 | P1 | `escape_markdown_text` escaped backticks, underscores and periods, so authored code spans in page titles (for example the guided-tour titles referencing `gpt_config.py`) rendered with literal backslashes in the static resource list, visible on the deployed page. | Fixed: the function escapes only backslash, asterisk and square brackets; committed `generated-map-list-{fr,en}.qmd` regenerated with the new rule. |
| LM-02 | P1 | The committed guided-route fragments still described the six-stage route while `data/guided-route.yml` and the membership tests had moved to eight stages, leaving `test_guided_route_freshness` failing on main. | Both fragments regenerated for the eight-stage route. |
| LM-03 | P2 | Both page shells announced a six-stage route ("Six étapes conceptuelles…" / "Six conceptual stages…"). | Updated to eight in FR and EN. |
| LM-04 | P2 | Search results did not update the status region: no match count, and the empty-result state was not announced. | `renderSearchResults` reports both states through `setStatus`. |
| LM-05 | P2 | Map state was invisible to the URL: a territory, a concept selection or the concepts view could not be linked. | The map mirrors `mode`, `area`, `concept` and `q` in the hash and restores them on load (`history.replaceState`, no back-navigation noise). |
| LM-06 | P3 | The "Explorer les ressources" section repeated almost the whole territory/section/page explanation already given at the top of the page. | Condensed into a short pointer; controls and provenance notes kept. |
| LM-07 | P3 | The page opted out of the site-wide TOC (`toc: false`) despite being one of the longest pages, leaving the stage anchors unreachable from the outline. | `toc: true` in both shells (site default depth 3). |
| LM-08 | P3 | Both shells lacked the `description` front-matter field used by other entry-point pages. | Descriptions added in FR and EN. |
| LM-09 | P3 | French route objective "Suivre la consultation des embeddings" was ambiguous (an embedding-table lookup, not a consultation). | Reworded to "Suivre la lecture des vecteurs d'embedding…"; the EN objective already said "embedding lookup". |

## 2. Verified non-defects

- The `generation` page appearing in two stages (orientation and inference) is intentional: the multi-membership context renderer presents the page honestly at each point it occurs.
- The interactive map already renders a visible breadcrumb inside a territory and implements the documented Escape drill-up.
- `site/includes/language-switch.html` already injects a header language toggle; the bottom-of-page language link is a harmless secondary affordance.

## 4. Verification notes

- The escaping change keeps backslash, asterisk and square brackets escaped, which is what `test_render_resource_list_nests_areas_sections_and_pages` asserts (an italic marker in a title stays escaped, structure unchanged).
- The committed fragments were regenerated by hand-applying the generator's rendering rules; `test_guided_route_freshness` is the authoritative check and fails the PR if any byte differs.
- The browser-script changes preserve every contract asserted by `tests/site/test_learning_map.py` (node selection, keyboard activation, legend, reset and concept-group filters).
- Quarto front-matter changes (`description`, `toc`) are additive and validated by the page-map parsers and `test_reader_metadata_visibility.py`.

## 5. Limitations

- No rendered-browser walkthrough: JavaScript changes were reviewed against the existing script contracts only.
- Learner comprehension, responsive layout and screen-reader behaviour of the new hash state were not empirically tested.
